# Vue

Our Vue integration works with Vue 3 (SPAs as well as server side rendered apps)
and with Nuxt.

## Installation

To get started make sure to install the package using your favorite package manager.

<Tabs items={["npm", "yarn", "pnpm"]}>
  <Tab>
    ```bash
    npm i @tryabby/vue
    ```
    </Tab>

  <Tab>
    ```bash
    yarn add @tryabby/vue
    ```
</Tab>
  <Tab>
    ```bash
    pnpm i @tryabby/vue
    ```
    </Tab>
</Tabs>

## Usage

### Create your config

To use Abby you need to create your config first. You can do this by creating a
file called `abby.config.ts` in your `root` folder. This file will be used to
configure your project.

```ts
// abby.config.ts
import { defineConfig } from "@tryabby/vue";

export default defineConfig({
  projectId: "<YOUR_PROJECT_ID>",
  currentEnvironment: import.meta.env.MODE,
  environments: ["production", "development"],
  tests: {
    test: { variants: ["A", "B"] },
    footer: { variants: ["dark", "orange", "green"] },
    // ... your tests
  },
  flags: ["darkMode", "newFeature"],
  remoteConfig: {
    customButtonText: "String",
  },
});
```

### Create your instance

To use Abby in your code you will need to create your typed composables first.
You can do this by using the `createAbby` function. Please copy the id of your
project from the dashboard to get started.

```ts
import { createAbby } from "@tryabby/vue";
import abbyConfig from "../abby.config";

const { AbbyProvider, useAbby } = createAbby(abbyConfig);
```

<Callout type="info">
  Call `createAbby` once in its own module and import the returned composables
  where you need them - that keeps the types of your tests, flags and remote
  config available across your whole app.
</Callout>

### Wrap your Application

Wrap your application in the `AbbyProvider`. The provider loads your project
data and provides it to all components below it.

```html
<script setup lang="ts">
  import { AbbyProvider } from "./abby";
</script>

<template>
  <AbbyProvider>
    <RouterView />
  </AbbyProvider>
</template>
```

If you prefer to use a plugin you can also install Abby on your app instance.
The composables need to be created outside of your components for this.

```ts
// main.ts
import { createApp } from "vue";
import { AbbyPlugin } from "./abby";
import App from "./App.vue";

createApp(App).use(AbbyPlugin).mount("#app");
```

### Use the composables

The composables can be used inside the `setup` function of your components. They
all return `ComputedRef`s, so they stay in sync when new project data arrives.

#### useAbby

`useAbby` takes the name of your test and returns the currently selected variant
as well as the `onAct` function, which you can call to track a conversion.

```html
<script setup lang="ts">
  import { useAbby } from "./abby";

  const { variant, onAct } = useAbby("test");
</script>

<template>
  <div>
    <p v-if="variant === 'A'">Variant A</p>
    <p v-else>Variant B</p>

    <button type="button" @click="onAct">Buy now</button>
  </div>
</template>
```

#### useFeatureFlag

`useFeatureFlag` takes the name of your feature flag and returns its value.

```html
<script setup lang="ts">
  import { useFeatureFlag } from "./abby";

  const darkModeEnabled = useFeatureFlag("darkMode");
</script>

<template>
  <div :class="{ dark: darkModeEnabled }">Hello World</div>
</template>
```

#### useRemoteConfig

`useRemoteConfig` takes the name of your remote config and returns its value.

```html
<script setup lang="ts">
  import { useRemoteConfig } from "./abby";

  const buttonText = useRemoteConfig("customButtonText");
</script>

<template>
  <button type="button">{{ buttonText }}</button>
</template>
```

### Nuxt

For Nuxt you can put your `createAbby` instance into a plugin and pass the
project data which is fetched during server side rendering as `initialData`.
This way the first render already contains your variants and flags.

```ts
// plugins/abby.ts
import { createAbby } from "./abby";

const { AbbyPlugin } = createAbby(abbyConfig);

export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.vueApp.use(AbbyPlugin);
});
```

<Callout type="info">
  `AbbyProvider` accepts an `initialData` prop (an `AbbyDataResponse` from
  `@tryabby/core`). If you pass it, the provider will not fetch your project data
  on the client, which avoids a hydration mismatch.
</Callout>
